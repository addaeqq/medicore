SUGGESTED 5-MINUTE WALKTHROUGH
-------------------------------------------------------------------------------
1. patient@medicore.test    Overview -> My bills -> the GHS 125.00 invoice ->
                            "Pay GHS 125.00" opens the ITC Transflow UAT checkout.
                            Test card 5123450000000008, CVV 100, expiry any 01-39.
                            The invoice settles to PAID after the gateway is
                            independently re-checked (never on the callback alone).

2. doctor@medicore.test     "My queue" -> three patients waiting -> "Start
                            consultation" -> write notes -> "Sign & lock". The note
                            then cannot be edited: corrections are addendums only,
                            enforced by a database trigger.

3. c.adjei@medicore.test    "Ward board" -> the occupied bed -> "Open chart" ->
                            file observations. This nurse can only reach patients
                            admitted to her own ward (access control AC-03).

4. d.ofori@medicore.test    "Bench worklist" -> open a request -> collect sample ->
                            start processing -> enter results. The laboratory
                            cannot release results to the patient; only the
                            ordering doctor can.

5. pharmacist@medicore.test "Dispensing & stock" -> a prescription -> dispensing
                            draws the earliest-expiring batch first, and low stock
                            is flagged in red.

6. admin@medicore.test      "Staff" -> create a staff account, deactivate a leaver,
                            clear a lockout. "Schedules" -> publish a weekly clinic.

-------------------------------------------------------------------------------
NOTES FOR THE EXAMINER
-------------------------------------------------------------------------------
* All data is synthetic. No real patient data is present anywhere in the system.

* Payments run against the ITC Transflow UAT environment with vendor test
  instruments. No real money moves.

* The demonstration accounts deliberately share one password so that the whole
  system can be examined quickly. This is a demonstration setting, not a
  production one; the seed is disabled and passwords rotated before real use.

* The application is deployed on Railway with two services (web and API) and a
  managed PostgreSQL instance. If a page briefly returns "rate limited", that is
  Railway's edge throttling on the trial plan, not the application — wait a
  moment and retry.

* Source repository access: if the repository is private, request access for the
  examiner account and it will be granted.
